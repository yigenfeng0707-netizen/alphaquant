## P1 后端改造：启动预热 + 未知 API 404 JSON

`backend/app/main.py`：

- **启动预热**：新增 `lifespan`（asynccontextmanager），进程内通过 `httpx.ASGITransport` 对 4 个业务端点各预热一次（`WARMUP_PATHS`，总超时 120s，失败不阻断启动），预热完成后才对外 READY。实测首轮各端点约 3s 内完成，数据源加载与计算缓存填充后，公网首访 TTFB 由冷启动约 2s 降至 0.2s 级。
- **404 JSON**：`spa_fallback` 区分 API 与前端路由——`/api/*`（含裸 `/api`）未知路径返回 `JSONResponse({"ok": False, "error": "api endpoint not found"}, 404)`；其余未知路径仍走 SPA fallback 返回 index.html。
- 新增 `GZipMiddleware(minimum_size=500)`（CORS 之后注册）。

**验证**：后端 `pytest` 58 passed；本地启动后 4 业务端点 200+JSON+ok:true、`/api/offline/cases` 与 `/api/does-not-exist` 返回 404 JSON、`/some/vue/route` 返回 200 HTML；公网 404 JSON 同样生效。

## P3 TLS1.3 评估结论：魔搭侧不可控 → 降级/豁免

**结论：TLS1.3 在魔搭侧不可配置，维持 TLS1.2 属平台托管限制，予以豁免。** 原因与证据：

- 魔搭空间对外由阿里云 WAF + EAS 托管，出口协议与密码套件不可自定义，TLS 协商由平台/边缘层决定。
- 三工具交叉验证（Python ssl / curl / openssl）：强制 TLS1.3 握手均报 `tlsv1 alert protocol version`（alert 70）；openssl 默认协商结果为 `Protocol: TLSv1.2`、`Cipher: ECDHE-RSA-AES128-GCM-SHA256`。
- 响应头含 `acw_tc`（阿里云 WAF 特征）与 `X-Eas-Instance: studio-gsym236998-alphaquant-*`（EAS 容器实例），佐证请求经阿里云 WAF/EAS 边缘进入。

**影响评估**：TLS1.2（ECDHE-RSA-AES128-GCM-SHA256）为当前互联网主流通用协议，兼容性覆盖浏览器/客户端广泛；演示系统无强制 TLS1.3 的业务要求，不构成安全或功能缺陷。若未来需要 TLS1.3 专属策略，应改走自建域名 + 自有网关/CDN（超出本演示项目范围，不做）。
